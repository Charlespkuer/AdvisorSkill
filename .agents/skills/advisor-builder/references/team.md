# Work with an advisor group

- Resolve the named team and its local checkout before handling evidence. Start from a team repository or directory approved by the author. For repositories, verify the intended remote and that it is private before committing or sending feedback. Ask only if the intended team is ambiguous or repository visibility cannot be established.
- To contribute, use the personal workspace's task packet to select the exact evidence IDs. Use a group-agreed manuscript slug and a unique round slug. Show the author the comment, related excerpts, and source metadata to be shared, along with the destination and audience. Run `advisorskill team contribute` to get a digest. Pass `--approve DIGEST` only after the author authorizes the selected records and destination. Stage only the resulting batch when the author has authorized a Git submission.
- When reviewing a contribution, pull the trusted team checkout and run `advisorskill team sync` into a dedicated team workspace, then use `prepare` and `review` against that workspace. The task packet maps feedback IDs to manuscripts in `team.feedback_papers`. Preserve concrete word-choice cases and distinguish independent manuscripts from repeated versions of one draft. After a maintainer decides, run `team record --approve` or `--reject` and submit only the resulting decision file through the private review workflow.
- To use the shared guide, update the selected private checkout and sync into the team's dedicated workspace. Build that workspace into the selected project's skill directory and use the approved rules. The build reads the team workspace locally; provide original excerpts to the agent only when the task needs that context and the author has authorized its use.
- A context correction needs its original record or another previously shared correction for the same manuscript. Include the parent only if the author authorizes sharing it.
- For public sharing, use the separate public-guide workflow with authorization from the team or relevant rightsholders. Keep team batches, review packets, and decisions in their private locations.

The project guide at `docs/team.md` shows the command sequence.
